## 1. 배정과 수강을 왜 나눴나

- **assignment** = 관리자의 의도("개발팀에 이 코스를 11월 20일까지"), **enrollment** = 한 사람이 한 코스를 듣는다는 사실.
- 부서 배정 하나가 여러 사람의 수강으로 펼쳐지고, **나중에 그 부서로 온 사람도** 활성 배정을 보고 수강이 생긴다. 의도를 따로 저장하지 않으면 신규 입사자 처리가 불가능하다.
- 부서 배정과 개인 배정이 겹쳐도 수강은 하나다: `UNIQUE(membership_id, course_id)`.

## 2. 동시성은 DB 제약에 맡긴다

| 상황 | 방법 | 테스트 |
|---|---|---|
| 같은 사람에게 두 배정이 동시에 | `INSERT … ON CONFLICT DO UPDATE SET due_at = LEAST(old, new)` | 마감일이 더 이른 쪽으로, 늦은 배정이 마감을 미루지 못함 |
| 퀴즈 시작 버튼 두 번 | 부분 유니크 인덱스 `(enrollment_id) WHERE status = 'IN_PROGRESS'` + 열린 응시가 있으면 그것을 돌려줌 | 새로고침해도 같은 응시 |
| 퀴즈 제출 두 번 | `UPDATE … WHERE status = 'IN_PROGRESS'` → 0행이면 409 | 두 번째 제출 409 |
| 마지막 레슨 완료와 퀴즈 통과가 겹침 | `UPDATE enrollment … WHERE status <> 'COMPLETED'` → 1행일 때만 수료증 생성 | 수료는 정확히 한 번 |
| 하트비트 두 개가 동시에 | 진도 행 `SELECT … FOR UPDATE` | 인정 시간이 두 번 더해지지 않음 |
| 첫 레슨 열기 두 번 | `INSERT … ON CONFLICT DO NOTHING` | 진도 행 하나 |

- **"조회 후 생성"은 쓰지 않는다.** 두 요청이 동시에 "없음"을 보고 둘 다 넣는다. 제약은 경쟁할 수 없다.
- `LEAST`는 NULL을 무시하므로 "마감 없음" 수강에 마감 있는 배정이 오면 그 날짜가 적용된다. 완료된 수강은 건드리지 않는다(`WHERE status <> 'COMPLETED'`).

## 3. 멱등 키 (Idempotency-Key)

- 관리자가 버튼을 두 번 누르거나 네트워크가 재전송해도 **배정은 한 번**만 된다. 같은 키로 다시 오면 처음 응답을 그대로 돌려주고 `Idempotent-Replayed: true`를 붙인다. 같은 키에 다른 내용이면 422(클라이언트 버그).
- **설계 문서에서 바꾼 점:** 원래는 Redis에 24시간 보관하려 했는데, **DB 테이블에 같은 트랜잭션으로** 저장했다. Redis에 두면 "배정은 커밋됐는데 키 저장 전에 죽음" 또는 그 반대가 생길 수 있다. 같은 트랜잭션이면 둘 다 되거나 둘 다 안 된다. 동시에 같은 키가 오면 기본 키 충돌로 한쪽이 통째로 롤백되고, 컨트롤러가 저장된 결과를 돌려준다.
- 프론트는 폼 제출마다 키를 하나 만들고 **성공했을 때만** 새 키로 바꾼다. 실패 후 재시도는 같은 키라서 안전하다.

## 4. 신규 입사자와 부서 이동

- 초대 수락(`MemberJoined`)과 활성 멤버의 부서 변경(`MemberDepartmentChanged`) 때 `syncFor(멤버)`가 그 사람에게 해당하는 배정(부서 + 개인)을 수강으로 만든다. 기존 수강은 그대로 둔다(부서를 옮겨도 듣던 교육을 뺏지 않는다).
- **커밋 후, 별도 트랜잭션**(`@TransactionalEventListener` + `REQUIRES_NEW`)으로 돈다. 수강 생성이 실패해도 그 사람의 로그인이 롤백되면 안 되기 때문이다. 실패는 로그로 남고 업서트라 다시 돌려도 안전하다. Day 4에 아웃박스로 옮겨 자동 재시도한다.
- 이벤트 클래스는 tenancy 모듈의 공개 패키지에 있고, learning이 구독한다. **tenancy는 learning을 모른다.**

## 5. "끝으로 건너뛰어 수료" 막기: 인정 시간 규칙

```
인정 = clamp(이동량, 0, 경과 × 2 + 5초)     (마지막 하트비트 후 30분 넘으면 새 세션: 인정 0)
완료 = 인정 시간 ≥ ceil(영상 길이 × 0.9)
```
- 정상 재생은 전부 인정, 2배속까지 허용, 1,800초 점프는 35초만 인정, 뒤로 감기는 0(위치만 저장, 이어보기용).
- **영상 길이는 서버 값만 쓴다**(`video_asset.duration_seconds`). 브라우저가 보낸 길이를 믿으면 길이를 줄여 보내는 것만으로 완료된다. 단, **로컬의 가짜 변환기는 업로드 때 브라우저가 읽은 길이를 임시로 쓴다.** AWS에서는 MediaConvert 결과가 덮어쓴다. 이 차이를 숨기지 말 것.
- 경계값을 단위 테스트로 고정했다: 정확히 30분은 같은 세션, 30분+1초는 새 세션, 2배속 + 5초 상한, 61초 영상은 55초부터 완료(올림), 시계가 거꾸로 가면 0.
- **한계를 먼저 말한다:** 하트비트 자체를 위조하면 막을 수 없다. 목표는 가장 쉬운 꼼수를 막고 비용을 올리는 것. 규제가 있는 교육(환급 과정)은 본인 인증·모사 방지 요건이 따로 붙는다.
- **레슨 열기는 POST**다. 수강 시작, 재생 세션 시작, xAPI `launched`라는 효과가 있다. GET으로 두면 Next.js 프리페치만으로 "열린" 레슨이 생긴다.

## 6. 퀴즈와 수료

- **정답은 서버를 떠나지 않는다.** 학습자용 응답에는 `answer` 필드 자체가 없고(테스트로 확인), 결과는 문항별 정오만 준다.
- 복수 선택은 **정답 집합과 정확히 같아야** 점수. "전부 고르기"로 맞히는 길을 막는다. 단일 선택에 두 개를 고르면 오답.
- 제한 시간 + 30초 유예. 지나서 제출하면 0점이지만 **제출한 답은 기록에 남긴다**(분쟁 대응).
- 응시는 시작 시점의 `quiz_revision`을 기록한다. 그리고 **수강자가 있는 코스는 게시 취소가 안 된다**(409 `COURSE_IN_USE`). 그래서 응시 중에 문항이 바뀌는 일이 없다. 고치려면 보관 후 새 코스를 만든다.
- **수료 + 수료증 행 + 이벤트가 한 트랜잭션.** "수료는 됐는데 수료증이 영원히 안 생기는" 상태가 없다. PDF는 Day 4에 아웃박스 → 워커가 만든다. 수료번호는 `LMS-2026-XXXXXXXX`(헷갈리는 문자를 뺀 Crockford Base32).
- 퀴즈가 없는 코스는 마지막 레슨 완료로 같은 수료 로직을 탄다.

## 7. xAPI 학습 기록

- **왜 xAPI인가:** e-러닝 업계의 "누가 무엇을 했나" 교환 형식이다(actor · verb · object · result · context). 이 모양으로 저장하면 외부 LRS·분석 도구로 변환 없이 내보낼 수 있고, 동사도 ADL/cmi5 표준 IRI를 쓴다.
- **현재 상태와 기록을 나눴다.** `lesson_progress`는 덮어쓰는 현재 상태(화면용), `learning_record`는 추가만 하는 사건 기록(감사·분석용). 앱 계정에는 `learning_record`에 **INSERT만** 줬다. 수정·삭제는 `permission denied`(테스트로 확인).
- **같은 트랜잭션:** records 모듈이 동기 리스너로 받는다. 수료가 롤백되면 "completed" 문장도 없다.
- **중복 방지:** 진도 25/50/75%, 완료, 응시 결과는 **사건의 정체성으로 만든 UUID(v3)** 를 문장 ID로 쓴다. 재시도로 같은 문장이 오면 기본 키 충돌로 무시된다. `launched`는 열 때마다 다른 사건이라 무작위 ID.
- 하트비트마다 기록하지 않고 **25% 구간을 넘을 때만** `progressed`를 남긴다. 기록량을 100분의 1 수준으로 줄인다.
- 조회 API는 xAPI Statement API 모양(`GET /v1/xapi/statements?registration=수강ID` → `{statements: [...]}`).

## 8. 모듈 경계 — 순환 없이 서로 필요한 것을 얻는 법

- learning → catalog(코스 구조, 정답 키), files(재생 주소, 문서 링크), tenancy(부서원, 상태), organization(부서 이름).
- **catalog도 learning이 필요했다**("수강자가 있으면 게시 취소 금지"). 그대로 의존하면 순환이다. 그래서 **catalog가 질문(`CourseUsage`)을 선언하고 learning이 구현**했다(의존성 역전). `ModularityTest`가 순환이 없음을 검증한다.
- learning은 records를 모른다. 이벤트를 발행할 뿐이다. Day 4에 감사 로그·알림·수료증 모듈이 같은 이벤트를 구독한다.

## 9. 배포 코드 (적용하지 않음)

- AWS 계정 없이 **코드와 설계만** 썼다. 시연은 로컬. 상세는 [infra/terraform/README.md](../../infra/terraform/README.md).
- 검증: `terraform fmt`·`validate` 통과(Docker의 Terraform 1.17.1), Dockerfile 3개 로컬 빌드, 마이그레이션 전용 모드(`--lms.migrate-only=true`)가 로컬 DB에서 종료 코드 0.
- 면접에서 짚을 것: S3 네이티브 상태 잠금(DynamoDB 없음), GitHub OIDC 역할 2개(PR=읽기 전용, main=배포만), API에 공개 주소 없음(Service Connect), 마이그레이션은 owner 계정을 가진 일회성 태스크, 비밀값은 시작할 때 주입, 서명 쿠키가 필요한 이유, 회로 차단기 롤백, 불변 이미지 태그.
- **못 한 것:** plan/apply, IAM 정책이 실제로 충분한지(적용 후 AccessDenied로 드러남), 서명 쿠키 발급 코드.

## 10. 브라우저 확인 중 고친 것

- 모든 교육을 수료하면 "배정된 교육이 없습니다"가 뜨고 수료 목록까지 사라졌다 → 수료 목록은 남기고 "지금 들어야 할 교육이 없습니다"로. 스토리(`AllCompleted`)로 고정.
- BFF 패스스루가 `Idempotency-Key` 헤더를 버리고 있었다 → 전달 목록에 추가(응답의 `Idempotent-Replayed`도).
- 게시된 코스의 퀴즈 편집기에 "보기 추가" 버튼이 보였다 → 편집 가능할 때만.
- 수료 목록 설명이 아직 없는 PDF 다운로드를 약속했다 → 문구 수정.
