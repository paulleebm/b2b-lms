# 06. 보안 설계 — 무엇을 지키고, 무엇으로부터, 어떻게

> 보안은 기능 목록이 아니라 **"누가 무엇을 노리는가"에서 출발**한다. 위협을 먼저 정리하고 대응책을 연결했다.

## 1. 지켜야 할 자산

| 자산 | 왜 중요한가 |
|---|---|
| 다른 회사의 데이터 | 유출되면 B2B SaaS는 끝이다 |
| 직원 개인정보 (이름, 이메일, 부서, 학습 이력) | 개인정보보호법 대상 |
| 계정, 특히 ORG_ADMIN | 탈취되면 회사 전체 데이터에 접근 |
| 교육 콘텐츠 | 고객사의 사내 자산 |
| 수료 기록, 수료증 | 의무교육 증빙 → **위조되면 안 됨** |
| AWS 계정과 인프라 | 탈취되면 데이터 전체 + **요금 폭탄**(채굴 등) |

## 2. 위협과 대응 (OWASP Top 10 기준)

| # | 위협 | 이 서비스에서의 예 | 대응 |
|---|---|---|---|
| A01 | **접근 제어 실패** | A회사 멤버가 B회사 코스 조회, 학습자가 관리자 API 호출, 강사가 남의 코스 수정 | 토큰 조직 + **DB 멤버십 확인**, Hibernate `@TenantId`, **RLS**, `@PreAuthorize`, 서비스 소유권 검사, 교차 테넌트 테스트, 타 테넌트는 404 |
| A02 | **암호화 실패** | 토큰·개인정보 유출 | 비밀번호는 Keycloak이 보관(우리 DB엔 없음), 전 구간 TLS(ACM), RDS·S3 저장 시 암호화(KMS), 브라우저엔 토큰 없음(BFF) |
| A03 | **인젝션** | SQL 인젝션 | JPA 파라미터 바인딩, `JdbcClient`는 `?` 바인딩만 허용, 문자열 이어 붙인 SQL 금지(코드 리뷰 + CodeQL), React 기본 이스케이프 |
| A04 | **안전하지 않은 설계** | 영상 건너뛰기 수료, 정답 노출, 중복 제출, 남의 도메인으로 SSO 가로채기 | 서버 측 시청 시간 규칙, 정답은 DTO에서 제외, 조건부 UPDATE, 이메일 도메인 소유 확인(Should) |
| A05 | **보안 설정 오류** | 디버그 정보 노출, S3 공개, Actuator 노출, Swagger 공개 | ProblemDetail(스택 숨김), **S3 퍼블릭 접근 전면 차단**, Actuator는 health만 노출, 운영 Swagger UI 끔, 보안 그룹 최소 허용 |
| A06 | **취약한 구성 요소** | 패치가 끊긴 라이브러리·이미지 | Dependabot, **Trivy 이미지 검사**, CodeQL, 베이스 이미지 정기 갱신, 라이선스 검토(iText AGPL 제외) |
| A07 | **인증 실패** | 무차별 대입, 계정 열거, 토큰 탈취, 세션 고정 | Keycloak 무차별 대입 탐지·잠금, 관리자 OTP, PKCE·state·nonce, Refresh 회전·재사용 감지, `__Host-` 세션 쿠키, 로그인 후 세션 ID 재발급 |
| A08 | **무결성 실패** | 수료 기록 조작, 배포 이미지 바꿔치기 | 감사 로그·xAPI 기록 INSERT 전용, 수료증 진위 확인, **커밋 해시 이미지 태그**, OIDC 배포(장기 키 없음) |
| A09 | **로깅·모니터링 실패** | 공격당해도 모름 | 감사 로그, OpenTelemetry 트레이스, Keycloak 로그인 이벤트, CloudWatch 알람, **AWS Budgets 알람** |
| A10 | **SSRF** | 서버가 사용자 입력 URL 호출 | 사용자 URL을 서버가 호출하는 기능 없음. SSO 설정의 IdP URL은 관리자 입력이므로 **https만 허용 + 내부 주소 대역 차단** |

## 3. 계층별 보안 장치

```
[엣지]      ALB TLS 종료(ACM), HTTP→HTTPS 리디렉션, (운영: AWS WAF 관리형 규칙)
[네트워크]  DB·Redis는 프라이빗 서브넷, 보안 그룹끼리 참조해 최소 허용, 태스크 인바운드는 ALB에서만
[브라우저]  토큰 없음 — __Host-session 쿠키(HttpOnly·Secure·SameSite=Lax), CSP, HSTS, X-Frame-Options
[BFF]       PKCE·state·nonce, 서버 액션 Origin 검사, 세션은 Redis(즉시 폐기 가능)
[인증]      Keycloak: 비밀번호 정책, 무차별 대입 잠금, 관리자 OTP, Refresh 회전
[API 인증]  OAuth2 Resource Server: 서명(JWKS)·iss·aud·exp 검증
[인가]      DB 멤버십(즉시 반영) → @PreAuthorize → 소유권 검사 → @TenantId → RLS
[입력·출력] Bean Validation, 요청·응답 DTO 분리, RFC 9457(내부 정보 숨김)
[요청 제한] Bucket4j + Redis: 전역 / 회사 등록 / 초대 / 퀴즈 제출 각각 한도
[데이터]    lms_app 계정(RLS 우회 불가, 기록 테이블 INSERT만), 저장 시 암호화
[파일]      UUID 키, 타입·크기 제한, HeadObject 재검증, 짧은 서명 URL, CloudFront OAC,
            미완료 Multipart 1일 후 자동 중단(수명 주기 규칙)
[영상]      HLS + 경로를 영상 폴더로 좁힌 CloudFront 서명 쿠키(2시간), 서명 키는 SSM,
            MediaConvert 전용 역할(원본 읽기·출력 쓰기만), 워커는 작업 생성 + PassRole만
[비밀값]    SSM Parameter Store(SecureString), 이미지·코드·저장소에 비밀값 없음
[배포]      GitHub OIDC(단기 자격 증명), 최소 권한 배포 역할, Trivy, 커밋 해시 태그
[계정]      AWS 루트 계정 MFA + 사용 금지, IAM Identity Center로 일상 작업, CloudTrail
```

## 4. 자주 받는 질문

**Q. 왜 인증을 직접 안 만들었나요?**
"인증은 직접 만들지 않는다"가 업계 원칙이다. 비밀번호 해싱, 잠금, MFA, 토큰 회전, SSO는 작은 실수가 바로 사고가 되는 영역이다. 검증된 Keycloak에 맡기고, 우리는 **표준 프로토콜(OIDC)을 정확히 연결하고 인가를 설계하는 것**에 집중했다. OIDC라서 나중에 Auth0나 WorkOS로 바꿔도 API 코드는 거의 그대로다.

**Q. 브라우저에 토큰이 없으면 API는 어떻게 부르나요?**
브라우저는 Next.js(BFF)만 부른다. BFF가 Redis 세션에서 Access Token을 꺼내 Spring을 호출한다. XSS가 나도 훔칠 토큰이 없다. 그렇다고 XSS가 괜찮은 건 아니다. 공격자가 피해자 브라우저에서 **BFF를 통해 요청을 보낼 수는** 있다. 그래서 CSP, React 기본 이스케이프, `dangerouslySetInnerHTML` 금지로 XSS 자체를 막는 게 여전히 1순위다.

**Q. 세션 쿠키를 쓰면 CSRF는?**
① `SameSite=Lax`라서 다른 사이트의 POST에는 쿠키가 안 붙는다. ② Next.js 서버 액션은 `Origin` 헤더를 확인한다. ③ BFF 라우트 핸들러도 상태를 바꾸는 요청은 `Origin`을 검사한다.

**Q. RLS가 있는데 Hibernate `@TenantId`는 왜 또 쓰나요?**
다층 방어다. `@TenantId`는 **앱에서 빨리, 명확하게** 테넌트 조건을 적용하고, RLS는 **앱이 실수해도** 막는 최후의 방어선이다. `JdbcClient`처럼 Hibernate를 우회하는 SQL도 RLS가 막는다. CI는 "모든 테넌트 테이블에 RLS 정책이 있는가"까지 검사한다.

**Q. 멤버를 비활성화하면 바로 막히나요?**
그렇다. Spring이 요청마다 DB 멤버십 상태를 확인하고(캐시 60초, 변경 시 즉시 삭제), 동시에 Keycloak 세션을 끊는다. **토큰은 "로그인할 때의 사실", 멤버십은 "지금의 사실"** 이다. 순수한 무상태 JWT만 쓰면 만료 전까지 막을 수 없는데, 이 설계가 그 고전적인 트레이드오프를 푼다.

**Q. 영상 주소를 복사해서 다른 사람에게 주면?**
CloudFront 서명 쿠키는 **2시간 뒤 만료**되고 **그 영상 폴더 경로에서만** 유효하다. 쿠키 없이 주소만 복사하면 재생되지 않는다. 다만 로그인한 사람이 화면을 녹화하거나 파일을 받아 저장하는 것까지는 막지 못한다. 그건 **DRM**(유료 계약)의 영역이고, 유료 콘텐츠를 다루게 되면 검토한다고 답한다.

**Q. AWS 계정 보안은?**
루트 계정은 MFA를 걸고 쓰지 않는다. 일상 작업은 IAM Identity Center 사용자로 한다. CI는 OIDC로 **배포 권한만 있는 역할**을 잠시 빌린다. 코드 어디에도 AWS 키가 없다. 예산 알림으로 비정상 과금을 바로 안다.

## 5. 이번 범위에서 하지 않은 것

| 항목 | 이유 | 하게 된다면 |
|---|---|---|
| AWS WAF | 월 고정 비용 | 관리형 규칙(OWASP, 봇) + Rate 기반 규칙 |
| GuardDuty, Security Hub | 비용, 시연 효과 적음 | 계정 위협 탐지, 보안 점수 |
| 이메일 도메인 소유 검증 | Should | DNS TXT 레코드 확인 후 SSO 자동 라우팅 허용 |
| SCIM 프로비저닝 | 고객사 IdP 환경 필요 | 퇴사자 자동 비활성화 |
| 개인정보 컬럼 암호화 | 키 관리 체계 필요 | KMS 기반 애플리케이션 암호화 |
| 데이터 보존·파기 정책 실행 | 법무 검토 필요 | 퇴사 N년 후 익명화 배치 |
| 업로드 파일 악성코드 검사 | 시간 | S3 이벤트 → 검사 → READY 전환 |
| 모의해킹, ISMS-P 인증 | 비용·기간 | 외부 진단 |
