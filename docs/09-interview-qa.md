# 09. 예상 질문과 답

> 답은 **결론 → 이유 → 대안과 포기한 것 → 근거(코드·테스트)** 순서로 짧게. 길게 말할 거리는 각 Day 노트와 설계 문서에 있다.

---

## 아키텍처 전반

### 1. 왜 마이크로서비스가 아니라 모듈러 모놀리스인가요?

- **결론:** 한 사람이 5일 동안 만드는 규모에서 서비스를 쪼개면 얻는 것보다 잃는 것(분산 트랜잭션, 배포 파이프라인 N개, 네트워크 장애)이 크다.
- **대신 경계는 지켰다:** Spring Modulith로 모듈(tenancy, organization, catalog, learning, files, records, notification, reporting, audit)을 나누고, 다른 모듈의 `internal` 패키지를 참조하면 **테스트가 실패**한다(`ModularityTest`). 모듈 간 연결은 공개 인터페이스나 이벤트뿐이다.
- **언제 쪼개나:** 부하 특성이 다른 부분이 생길 때. 이미 그 첫 단계를 했다: 같은 이미지를 `WORKER_ENABLED=true`로 띄운 **worker 서비스**가 큐를 처리한다. 영상 변환이나 PDF 생성이 무거워지면 그 모듈부터 떼어낸다. 모듈 간 통신이 이미 이벤트라서 큐로 바꾸기만 하면 된다.

### 2. 요청 하나가 들어와서 DB까지 가는 과정을 설명해 주세요.

브라우저(세션 쿠키) → Next.js BFF가 Redis에서 토큰을 꺼내 `Authorization: Bearer` → API가 **JWKS로 서명 검증** → 토큰의 조직을 **우리 DB의 현재 멤버십으로 다시 확인**(토큰을 믿지 않고 회사·역할 결정) → `@PreAuthorize` → 트랜잭션이 커넥션을 꺼낼 때 `set_config('app.tenant_id', …, true)` → Hibernate `@TenantId`가 조건 추가 → **RLS가 최종 방어** → 반납할 때 초기화. ([03 아키텍처](03-architecture.md))

## 멀티테넌트

### 3. 회사 간 데이터 격리를 어떻게 보장하나요? 개발자가 실수로 WHERE를 빼먹으면요?

- **두 겹이다.** 앱: Hibernate `@TenantId`가 모든 JPA 쿼리에 회사 조건을 넣는다. DB: PostgreSQL **RLS(FORCE)**가 직접 쓴 SQL도 막는다.
- 앱 계정(`lms_app`)은 **테이블 소유자가 아니라서 RLS를 우회할 수 없다.** 마이그레이션은 별도 소유자 계정만.
- 테스트로 증명: 다른 회사 리소스는 404(존재 자체를 숨김), 직접 SQL도 0행, **새 테넌트 테이블을 만들고 RLS를 안 켜면 테스트 실패**(`RlsPolicyCoverageIT`), 커넥션 풀에서 이전 회사 값이 남지 않음(`ConnectionPoolTenantLeakIT`).
- 외래 키도 `(tenant_id, id)` 복합 키라서 A사 수강이 B사 코스를 가리킬 수 없다.

### 4. RLS 말고 회사별 스키마나 DB를 나누는 방법은요?

| 방식 | 장점 | 단점 |
|---|---|---|
| 회사별 DB | 가장 강한 격리, 회사별 백업 | 회사 1000개 = DB 1000개. 마이그레이션·커넥션 관리 지옥 |
| 회사별 스키마 | 중간 | 스키마 수만큼 마이그레이션, 커넥션 풀 분리 |
| **공유 테이블 + RLS** | 운영 하나, 회사 추가 비용 0 | 격리를 코드와 정책으로 증명해야 함 → 테스트로 증명 |

B2B SaaS 초기에는 공유 테이블이 표준이고, 큰 고객이 전용 환경을 원하면 그 회사만 분리하는 혼합형으로 간다.

### 5. 캐시나 큐처럼 RLS 바깥에서는요?

- **캐시 키에 회사 ID를 반드시 넣는다**(대시보드 `key = tenantId`). 빠지면 A사가 B사 숫자를 본다. RLS가 막아주지 못하는 곳이라서 가장 조심한 부분.
- **큐 메시지에 회사 ID를 담고**, 워커는 그 회사 컨텍스트 안에서 처리한다. 워커도 RLS를 지난다.
- 로그인 없는 **수료증 진위 확인**은 RLS를 끄지 않고, 수료번호 한 건만 가려서 돌려주는 `SECURITY DEFINER` 함수 하나만 열었다.

## 인증

### 6. 인증을 왜 직접 만들지 않았나요? 왜 BFF인가요?

- 비밀번호 저장·재설정·MFA·SSO·세션 관리는 실수하면 사고다. **Keycloak**(오픈소스, Red Hat)의 Organizations로 "회사 = 조직", 이메일 도메인으로 회사 SSO까지 설정으로 된다. Auth0·Cognito도 봤지만 비용(MAU 과금)과 조직 기능에서 Keycloak을 골랐다.
- **BFF**: 브라우저에는 `HttpOnly` 세션 쿠키만, 토큰은 서버(Redis)에. XSS가 나도 토큰을 훔쳐갈 수 없다. IETF "Browser-Based Apps" 권고안이 권하는 방식. 토큰 갱신이 동시에 일어나면 리프레시 토큰 회전 때문에 하나가 실패하므로 **Redis 분산 락**으로 한 번만 갱신한다.

## 동시성과 신뢰성

### 7. 관측성은?

- 지금: 로그마다 `traceId`·`tenantId`(MDC), 에러 응답(RFC 9457)에도 `traceId`. AWS에서는 **JSON 로그(ECS 형식)** → CloudWatch Logs Insights. 알람은 ALB 5xx, DLQ 적재, 월 예산.
- 붙일 것: Spring Boot의 Micrometer Tracing + OTLP 내보내기 → OpenTelemetry Collector → Grafana Cloud(Tempo·Loki·Prometheus). BFF에서 `traceparent` 헤더를 넘기면 브라우저 요청부터 DB까지 한 줄로 이어진다. 에러 추적은 Sentry.

### 8. 같은 요청이 두 번 오면요? (버튼 두 번, 네트워크 재전송)

- **배정**: `Idempotency-Key` 헤더. 키와 응답을 **업무 데이터와 같은 트랜잭션으로 DB에** 저장. 같은 키면 처음 응답 + `Idempotent-Replayed: true`, 같은 키에 다른 내용이면 422. 처음엔 Redis를 생각했지만 "배정은 됐는데 키 저장 전에 죽음"이 생길 수 있어 DB로 바꿨다.
- **수강 생성**: `INSERT … ON CONFLICT DO UPDATE SET due_at = LEAST(…)` — 조회 후 생성을 쓰지 않는다.
- **퀴즈 제출·수료**: 조건부 UPDATE(`WHERE status = 'IN_PROGRESS'`)가 0행이면 이미 처리됨. 수료는 정확히 한 번.
- **큐 메시지**: `processed_message (message_id, handler)` 기본 키 + `ON CONFLICT DO NOTHING`, 처리와 같은 트랜잭션.

### 9. 아웃박스 패턴을 설명해 주세요.

DB 커밋과 메시지 전송은 한 트랜잭션으로 묶을 수 없다(이중 쓰기). 그래서 이벤트를 **업무 데이터와 같은 트랜잭션으로 DB 테이블에** 적고, 커밋 후 릴레이가 SQS로 보낸다. 실패하면 행이 남아 1분마다 재발행(ShedLock으로 한 대만). 결과는 "최소 한 번" 전달이므로 소비자는 멱등. 5번 실패하면 DLQ + 알람. 직접 만들지 않고 Spring Modulith의 이벤트 레지스트리를 썼다. Debezium(CDC)은 Kafka Connect가 필요해 이 규모엔 과하다. ([Day 4 노트](notes/day4.md))

### 10. 영상 시청 진도를 조작하면요? (개발자 도구로 "다 봤다" 요청)

- 서버는 클라이언트가 보낸 위치를 믿지 않는다. **인정 시간 = clamp(이동한 위치, 0, 실제 경과 시간 × 2 + 5초)**. 배속 2배까지만 인정하고, 앞으로 건너뛰면 인정되지 않는다. 30분 넘게 끊기면 새 세션.
- 90%(올림) 이상 인정되면 완료. 하트비트 두 개가 동시에 와도 진도 행을 `FOR UPDATE`로 잠가 두 번 더해지지 않는다.
- 경계값 단위 테스트 16개(`ProgressRulesTest`). 퀴즈 정답은 브라우저에 내려가지 않고 서버가 채점한다.

## 데이터와 표준

### 11. xAPI는 왜 넣었나요?

- 기업 교육 시장은 학습 기록을 다른 시스템(HR, LRS)과 주고받는 표준이 필요하다. **xAPI 1.0.3** 문장(행위자·동사·대상·결과)으로 모든 학습 이벤트를 남긴다. SCORM은 오래된 패키징 표준이라 범위에서 뺐다(01 문서).
- 기록은 **추가만 가능**(앱 계정에 INSERT·SELECT 권한만). 문장 ID는 이벤트로부터 결정적으로 만든 UUID v3라서 같은 이벤트가 두 번 와도 문장은 하나.

### 12. 대시보드 쿼리가 느려지면요?

- 지금: JPA 엔티티 대신 `JdbcClient` 집계 SQL 한 번씩(N+1 없음) + 회사별 캐시 60초 + 수료·배정 커밋 후 캐시 비움.
- 커지면: (1) 인덱스 `(tenant_id, status, due_at)` 확인 → (2) 집계 테이블을 이벤트로 갱신(이미 이벤트가 있다) → (3) 읽기 전용 복제본. 순서대로, 측정하고 나서.

### 13. 수료증 PDF는 왜 iText가 아닌가요?

iText는 **AGPL**이라 서비스에 쓰면 소스 공개 또는 상용 라이선스. **OpenHTMLtoPDF**(LGPL) + Thymeleaf로 HTML/CSS로 디자인하고 **Pretendard 폰트를 내장**해 컨테이너에서도 한글이 깨지지 않는다. 헤드리스 Chrome은 워커 이미지가 무거워진다.

## 인프라와 비용

### 14. AWS에 정말 배포했나요?

- **아니다. 솔직하게 말한다.** Terraform 코드(모듈 7개)와 Dockerfile을 쓰고 `terraform validate`와 이미지 빌드까지 검증했다. 시연은 로컬 Docker Compose(Keycloak, Postgres, S3Mock, ElasticMQ=SQS, Mailpit=SES)로 한다.
- 이유: 비용(24시간 월 약 $140~150)과 5일 일정. 로컬 대체물이 **같은 프로토콜**(S3 API, SQS API, SMTP)이라 코드는 같고 주소만 다르다.
- 도메인 `bymile.site`는 사 두었고, 위임(가비아 → Route 53)·인증서·SES 인증까지 코드에 있다. 적용 순서: [Terraform README](../infra/terraform/README.md).

### 15. NAT 게이트웨이가 없던데요?

NAT는 켜두기만 해도 월 $40 이상. 시연 환경은 태스크를 퍼블릭 서브넷에 두고 **보안 그룹이 ALB(또는 web)에서 오는 것만** 받게 했다. 들어오는 경로는 같다. DB·Valkey는 0.0.0.0/0 경로가 아예 없는 프라이빗 서브넷. S3는 게이트웨이 엔드포인트(무료). 운영이라면 프라이빗 + NAT 또는 인터페이스 엔드포인트.

### 16. 배포가 실패하면요?

ECS **회로 차단기**(`rollback = true`): 새 태스크가 헬스체크를 계속 실패하면 이전 버전으로 되돌린다. 이미지 태그는 커밋 해시 + **불변(IMMUTABLE)**이라 롤백 대상이 정확하다. 마이그레이션은 서비스보다 먼저 **일회성 태스크**로 돌리고, 하위 호환되게 쓴다(열 추가 → 코드 배포 → 옛 열 삭제는 다음 배포).

## 회고

### 17. 가장 어려웠던 결정은?

**"멤버십을 토큰이 아니라 DB에서 확인한다."** Keycloak 토큰에 조직과 역할이 들어 있으니 그걸 믿으면 간단하다. 하지만 관리자가 누군가를 내보내도 그 사람의 토큰은 만료(5분) 전까지 유효하다. 그래서 토큰은 "누구인가"만 믿고, **"어느 회사의 무슨 역할인가"는 매 요청 우리 DB의 현재 멤버십**으로 결정했다. 요청마다 조회가 하나 늘지만, 역할 변경과 퇴사가 즉시 반영된다. 대가와 이유를 둘 다 말할 수 있는 결정이라서 골랐다.

### 18. 다시 한다면?

- CI를 **첫날** 붙인다. 토큰 권한 문제로 미뤘더니 테스트를 매번 손으로 돌렸다.
- 무거운 작업(이미지 빌드, Testcontainers)을 동시에 돌리지 않는다. Docker VM이 메모리 부족으로 죽어서 복구하는 데 시간을 꽤 썼다.
- E2E를 더 일찍. 하나뿐인 E2E가 단위 테스트로는 못 찾는 버그 두 개(라우트별 번들 복제, 개발 서버 무한 새로고침)를 찾았다.
